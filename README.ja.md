# MLB ポストシーズン サマリーサイト

[English](README.md) | **日本語**

**MLB ポストシーズンのグラフィカルなサマリー**に、任意のシリーズの
**AI による勝敗予測**を加えた、軽量なサーバーレス Web アプリです。
すべて TypeScript で実装し、AWS CDK によってワンコマンドで AWS へデプロイできます。

このプロジェクトは [Kiro University Challenge](https://kiro.dev/2026/university/)
最終試験への提出作品です。

> **審査員の方へ:** 7 つの必須レッスンと 2 つのボーナスをそれぞれどのように実証しているか、
> および関連ファイルへのリンクは [DEMONSTRATED_LESSONS.md](./DEMONSTRATED_LESSONS.md)（実証された教訓）
> を参照してください。

## 概要

- **シーズンセレクターによる複数シーズン対応** — アプリは年度を認識します。現在の年は
  **2026 年**で、セレクターは **2024・2025・2026**（デフォルトは 2026）を選べます。過去の
  シーズン（2024・2025）は**結果のみ**で、現在のシーズン（2026）がライブで進行中のものです。
- **グラフィカルなポストシーズン表示** — ワイルドカードラウンドからワールドシリーズまでの
  ブラケットを表示し、各シリーズ・両チーム・シリーズスコア・ステータスを示します。
- **シリーズ詳細** — シリーズごとの試合単位の結果（すべてのシーズンで利用可能）。
- **順位 / サマリーパネル** — 参加チームをリーグ別にまとめ、ポストシーズンの進行状況を表示します。
- **勝敗予測（追加機能、現在のシーズンのみ）** — 進行中シーズンのシリーズについて、優勢チーム・
  勝率・そして選定理由を説明する **AI 生成のナラティブ**を表示します。予測機能は**現在（進行中）
  のシーズンのみ**で提供され、完了したシーズンは最終結果のみを表示します。

数値の勝率はコード内の決定論的モデルで算出され（説明可能でユニットテスト済み）、
**Amazon Bedrock**（Anthropic Claude）がそれを文章に変換します。

認証はありません。公開・読み取り専用です。賭け事を目的とした製品ではありません。

## アーキテクチャ

![Architecture](docs/architecture.png)

編集可能な図は [`docs/architecture.drawio`](docs/architecture.drawio)（draw.io /
diagrams.net で開けます）です。ベクター形式のエクスポート
[`docs/architecture.svg`](docs/architecture.svg) と PNG（`docs/architecture.png`）も含まれています。

- **フロントエンド:** React + TypeScript（Vite）。**S3**（プライベート、Origin Access
  Control）にホストし、**CloudFront** 経由で配信します。
- **バックエンド:** **API Gateway HTTP API**（CORS 付き）の背後にある 2 つの **AWS Lambda**
  関数（Node 20）。ルート: `GET /bracket`、`GET /prediction`、`POST /prediction`。
- **データ:** **DynamoDB** がシーズンごとに集約済みブラケット JSON をキャッシュします。
- **AI:** **Amazon Bedrock**（`InvokeModel`）が予測ナラティブを生成します。
- **IaC:** **AWS CDK（TypeScript）**がワンコマンドデプロイ用にすべてをプロビジョニングします。

### モノレポ構成（npm workspaces）

| ワークスペース   | パッケージ      | 役割                                                 |
| --------------- | --------------- | --------------------------------------------------- |
| `shared/`       | `@mlb/shared`   | ドメイン型（`Bracket`・`Series`・`PredictionResponse`）、`TEAMS`、シーズン設定（`CURRENT_YEAR`・`SELECTABLE_SEASONS`・`seasonMode`）、同梱の 2024 + 2025 シードデータセット。 |
| `backend/`      | `@mlb/backend`  | Lambda ハンドラー、MLB クライアント + 集約、予測モデル、Bedrock ナラティブ。 |
| `frontend/`     | `@mlb/frontend` | React + Vite SPA（ブラケット・順位・予測パネル）とコミット済みの SVG 画像アセット。 |
| `infra/`        | `@mlb/infra`    | AWS CDK アプリ（S3 + CloudFront、HTTP API + Lambda、DynamoDB、Bedrock IAM）。 |

## MLB データ戦略

1. **まず DynamoDB キャッシュ。** `getBracket` は DynamoDB の `pk = BRACKET#<season>` を
   参照します。鮮度のあるキャッシュ済みブラケット（`ttl` 属性による TTL、約 15 分）はそのまま返されます。
2. **キャッシュミス時に MLB Stats API。** Lambda が公開 MLB Stats API
   （`https://statsapi.mlb.com/api/v1/schedule/postseason?sportId=1&season=YYYY`、API キー不要）
   を取得し、試合をシリーズに集約してキャッシュへ書き戻します。
3. **シードフォールバック（完了シーズン）。** ライブ API に到達できない場合は、同梱の
   `@mlb/shared` シードデータセットを使用し、テストやデモで決定論的に動作し続けます。
   フォールバックは **2024 と 2025 の両方**をカバーします:
   - `postseason-2024.json` — ドジャースがヤンキースを 4-1 で破る。
   - `postseason-2025.json` — ドジャースがブルージェイズを 4-3 で破る（ライブ MLB Stats API
     から集約した実際の結果）。

   フロントエンドもブラケットリクエストが失敗した場合はこれらのシードにフォールバックするため、
   オフラインでもデモが描画されます。
4. **2026 がライブ / 現在のシーズン。** 現在の年（2026）には同梱シードがなくライブ取得されます。
   アプリは空の、またはまだ始まっていない 2026 ポストシーズンを適切に処理し（壊れたブラケットの
   代わりに「まだ開始していません」というメッセージを表示）、集約処理はライブスケジュールが返す
   未確定ラウンドのプレースホルダーチームを許容します。

### シーズンと予測機能

シーズンセレクターは 2024・2025・2026（デフォルト 2026）を提供します。現在の年より厳密に前の
シーズンは**結果のみ**です。予測 UI は非表示になり、`/prediction` エンドポイントは数値予測の
代わりに結果のみのレスポンス（`mode: 'results'`）を返します。現在のシーズン（2026）は**予測可能**
なので、進行中のシリーズに対して予測機能が提供されます。`/prediction` は開始済みシリーズには
`mode: 'prediction'` を、まだ始まっていないシリーズには `mode: 'upcoming'` を返します。すべての
バリアントは HTTP 200 で返され、フロントエンドは `mode` で分岐します。

### 完了シリーズ: 予測はオフ

現在の予測可能なシーズン内であっても、すでに完了したシリーズ（`status === 'final'`）は、
投機的な予測ではなく**最終結果を表示します**。これは両方のレイヤーで強制されます:

- **バックエンド:** `/prediction` はシリーズを解決し、`final` であれば予測モデルを実行したり
  Bedrock を呼び出したりすることなく `mode: 'results'` を返します。
- **フロントエンド:** 完了シリーズのカードは「勝者を予測」ボタンを描画せず、代わりに
  **「シリーズ詳細を表示」**リンクを表示するため、完了シリーズに対して数値勝率が表示されることは
  ありません。

### 設定可能な予測精度

予測パネルには、モデルの確信度を調整するラベル付きの**精度（accuracy）**スライダーがあります。
`accuracy` は範囲 **`[0, 1]`** のシャープネス制御で、**デフォルトは `0.5`** です:

- `0.5`（デフォルト）は**恒等（identity）**変換で、従来のモデル挙動を変えません。
- **高い**精度（> 0.5）は優勢チーム寄りに予測を鋭くします（より確信的、最大 `0.95` まで）。
- **低い**精度（< 0.5）はコイントス寄りに和らげます（`0` は優勢チームをちょうど `0.5` に収束させます）。

勝率はどの精度値でも**常に `[0.5, 0.95]` の範囲に収まります**（プロパティテストでカバーされる
不変条件）。この制御はエンドツーエンドで配線されており、スライダーは `GET /prediction` に
**`&accuracy=<value>`** クエリパラメーターを付加します（`POST /prediction` のボディでも受け付け
られます）。例: `GET /prediction?seriesId=...&season=2026&accuracy=0.8`。`accuracy` が欠落または
無効な場合はデフォルトにフォールバックし、`400` を発生させることはありません。スライダーを
ドラッグするとデバウンスして予測を再リクエストし、優勢チーム・勝率・ナラティブをライブで更新します。

### 日本語 / 英語の言語切り替え

UI はヘッダーに **JA/EN 言語トグル**を備えています。**日本語がデフォルト**です。選択は
`localStorage`（キー `mlb.lang`）に永続化され、再読み込み時に復元されます。すべてのユーザー向け
文字列がローカライズされています（タイトル / サブタイトル、シーズンラベル、ステータス、ラウンド名、
凡例、順位、精度コントロールを含む予測パネル、試合詳細トグル、詳細ページ）。`TEAMS` マップに存在
しない未知 / プレビューのチーム ID は、生の `Team <id>` ではなく、ローカライズされた
プレースホルダー（EN は `TBD (#<id>)`、JA は `未定 (#<id>)`）で描画されます。

### 試合詳細トグルと完了シリーズの詳細ページ

- **デフォルトで折りたたまれる試合詳細。** 各シリーズカードは、試合単位のリストをシリーズごとの
  **試合を表示 / 試合を隠す**トグルの背後に隠し、折りたたまれた状態で始まります。これにより
  ブラケットがコンパクトに保たれ、従来の不揃いな（「ガタガタ」の）カード高さと列の整列の主な修正
  となります。
- **完了シリーズの詳細ページ + クライアントサイドルーティング。** SPA はパスベース（history）の
  クライアントサイドルーティング（`react-router-dom`）を使用します。完了シリーズは
  `/season/:season/series/:seriesId` の専用詳細ページにリンクし、試合単位の完全な結果を表示します。
  未知の ID は親切な「シリーズが見つかりません」ページを表示します。パスベースのディープリンクは、
  CloudFront が `403`/`404` レスポンスを `/index.html`（HTTP 200）に書き換えるため、本番でも機能し、
  SPA シェルが読み込まれて要求されたルートを描画します。

## Amazon Bedrock の利用

勝率は `backend/src/predict/` 内の透明なヒューリスティックで計算されます（現在のシリーズ進行度を
レギュラーシーズン勝率とブレンドし、`[0.5, 0.95]` にクランプ）。次に **Bedrock**
（`BEDROCK_MODEL_ID`、デフォルトは `us.anthropic.claude-haiku-4-5-20251001-v1:0`、クロスリージョン
推論プロファイル）が、簡潔な 2〜3 文のナラティブで選定理由を説明します。Bedrock がエラーになった
場合、エンドポイントは決定論的なテンプレートのナラティブへ適切に劣化するため、予測は常に返されます。

## 画像アセット

UI は `frontend/src/assets/` 配下の**実際のコミット済み SVG 画像アセット**（絵文字ではありません）
を使用します — ブランドロゴ、野球 / ダイヤモンドのヒーロー、リーグ / ワールドシリーズのマーク、
さらにチームごとの色で駆動される生成済みのチームカラー SVG バッジです。SVG は「実際の画像アセット」
要件を満たしつつ、リポジトリを軽量に保ちます。

## 前提条件

- **Node.js 20+**（ローカルのツールチェーンは Node 22 かもしれませんが、コードは Node 20 の Lambda
  ランタイムを対象とします）。
- シェル / セッションで有効な認証情報を持つ **AWS アカウント**（プロファイル、SSO、または環境変数）。
- 選択した Claude モデル（デフォルトは `us.anthropic.claude-haiku-4-5-20251001-v1:0`、クロスリージョン
  推論プロファイル）に対する **Amazon Bedrock のモデルアクセスがデプロイリージョンで許可されている
  こと**。デプロイ前に Bedrock コンソールでモデルアクセスを有効化してください。デフォルトが推論
  プロファイル ID（プレフィックス `us.`）なのは、現行世代の Claude Haiku モデルが推論プロファイル
  経由のオンデマンドでのみ呼び出せるためです。Lambda の IAM ポリシーは、推論プロファイルと、それが
  ルーティングし得る US リージョン全体の基盤モデルに対して `bedrock:InvokeModel` を付与します。
  モデルは `cdk deploy --context bedrockModelId=<id>` で上書きできます。
- CDK は **esbuild** で Lambda をバンドルします（Docker 不要）。

> **注:** デプロイ前に AWS 認証情報が有効で**かつ** Bedrock のモデルアクセスがリージョンで許可されて
> いる必要があります。リポジトリのビルド自体はライブの AWS / Bedrock 呼び出しを行いません。

## ワンコマンドデプロイ

リポジトリルートから、有効な AWS 認証情報の下で:

```bash
npm install && npm run build && npm run deploy
```

- `npm install` — すべてのワークスペースをインストールします。
- `npm run build` — 依存順にビルドします: `shared → backend → frontend → infra`。CDK が synth 時に
  `frontend/dist` を S3 ウェブサイトソースとしてパッケージするため、フロントエンドはデプロイ**前に**
  ビルドされる必要があります。
- `npm run deploy` — 順序付きビルドを再実行してから、`@mlb/infra` ワークスペースの `cdk deploy` を
  実行します。

### 初回セットアップ（CDK ブートストラップ）

対象アカウント / リージョンへの初回 CDK デプロイの場合、一度だけブートストラップします:

```bash
cd infra
npx cdk bootstrap
npx cdk deploy
```

（リポジトリルートからは `npm run bootstrap` のあと `npm run deploy` も実行できます。）

デプロイ後、スタックは出力を表示します:

- **ApiUrl** — HTTP API のベース URL。
- **DistributionDomainName** — ブラウザーで開く CloudFront ドメイン。
- **BucketName** — SPA をホストする S3 バケット。
- **TableName** — DynamoDB キャッシュテーブル。

### SPA が API を見つける仕組み（再ビルド不要）

同じ静的バンドルは**デプロイ時**に任意のデプロイ済み API へ向けられます。CDK がバケットルートに
`window.__API_BASE_URL__ = "<ApiUrl>";` を含む `/config.js` を書き込み、アプリバンドルより前に
`index.html` が読み込みます。実行時、SPA は `window.__API_BASE_URL__` を読み取り、ビルド時の
`VITE_API_BASE_URL`、最後にローカルのデフォルトへフォールバックします。

### デプロイせずに検証

AWS に触れずに CloudFormation テンプレートを検証するには:

```bash
npm run build        # SPA アセット用に frontend/dist が存在することを保証
npm run synth        # cdk synth -> infra/cdk.out（AWS 呼び出しなし）
```

## ローカル開発

```bash
npm install
npm run dev -w frontend     # Vite 開発サーバー（http://localhost:5173）
```

デフォルトでフロントエンドは API に `http://localhost:3000` を使用します。データのオプション:

- **オフライン / シードデータ:** ブラケットリクエストが失敗すると、SPA は自動的に同梱の
  `@mlb/shared` シード（2024 と 2025）へフォールバックするため、完了シーズンのブラケットは
  バックエンドなしで描画されます。
- **デプロイ済み API を指す:** `VITE_API_BASE_URL=<ApiUrl> npm run build -w frontend` でビルドするか、
  （デプロイ済みサイトのように）`/config.js` 経由で `window.__API_BASE_URL__` を設定します。

モノレポ全体でテストスイートと型チェックを実行:

```bash
npm test          # ワークスペース全体の Vitest（AWS SDK + MLB API はモック）
npm run typecheck # 全ワークスペースで厳格な TypeScript
```
