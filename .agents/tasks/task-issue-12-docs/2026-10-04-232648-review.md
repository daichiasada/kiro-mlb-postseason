### Diagram-vs-stack fidelity

Each diagram node maps to a real stack resource with matching attributes:

```
Browser ──HTTPS──▶ CloudFront ──OAC──▶ S3 (private, Block Public Access)
   │
   └──fetch──▶ API Gateway (HTTP API, CORS)
                 ├─GET /bracket─────▶ getBracket  (256MB/15s) ──▶ DynamoDB
                 │                                  └┄cache miss┄▶ MLB Stats API
                 └─GET+POST /pred───▶ getPrediction(512MB/30s) ──▶ DynamoDB
                                                     └─InvokeModel─▶ Bedrock
CDK (infra/) ┄provisions┄▶ MlbPostseasonStack (acct 051826704233 / us-east-1)
```

CloudFront's `REDIRECT_TO_HTTPS`, OAC origin, and the 403/404 → `/index.html` rewrites match the `errorResponses` and `viewerProtocolPolicy` in the stack. S3 is labelled private / Block Public Access, matching `BlockPublicAccess.BLOCK_ALL`, and the "deploy-time /config.js" note matches the single `BucketDeployment` that ships `Source.data('config.js', ...)` alongside the SPA asset. The API node's `GET /bracket` and `GET+POST /prediction` are exactly the two `addRoutes` calls. Lambda sizing (256MB/15s for `getBracket`, 512MB/30s for `getPrediction`), Node 20 runtime, DynamoDB `PAY_PER_REQUEST` + partition key `pk` + TTL attribute `ttl`, and the `~15min` note (confirmed by `DEFAULT_TTL_SECONDS = 60 * 15` in the Dynamo store) are all faithful.

The `getBracket → DynamoDB` edge ("cache read/write") plus the dashed `getBracket → MLB Stats API` edge ("cache miss: fetch + aggregate (seed fallback 2024/2025)") correctly render the `bracketService.getBracket` resolution order (cache → live fetch + write-back → seed fallback). The MLB node ("statsapi.mlb.com, public, no key") matches `client.ts` (`https://statsapi.mlb.com/api/v1/schedule/postseason?sportId=1&season=`, no key). The `getPrediction → DynamoDB` edge labelled "reads bracket (same cache/MLB path)" is an accurate depiction — `getPrediction` calls `getBracket` internally rather than hitting a distinct store — and the `getPrediction → Bedrock` "InvokeModel (narrative)" edge plus the model id `us.anthropic.claude-haiku-4-5-20251001-v1:0` and "deterministic fallback" note match `narrative.ts` (`DEFAULT_MODEL_ID`, cross-region inference profile, templated fallback). No edge implies `getBracket` calls Bedrock, which is correct — only the prediction path does.

The accepted icon deviation holds up: in the `.drawio` the Bedrock cell uses `resIcon=mxgraph.aws4.sagemaker` but the `value` is "Amazon Bedrock / InvokeModel / us.anthropic.claude-haiku-4-5-20251001-v1:0 / cross-region profile; deterministic fallback", which removes any ambiguity. The SVG does not inherit the limitation — it draws a Bedrock-teal (`#01A88D`) box titled "Amazon Bedrock (InvokeModel)".
