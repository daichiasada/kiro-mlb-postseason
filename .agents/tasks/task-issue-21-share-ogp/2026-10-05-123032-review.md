# Shareable per-series permalinks and OGP cards for the postseason SPA (v1)

Issue #21 makes a single series shareable: a localized Share button on the series detail page and prediction panel, a `?lang=` permalink that opens the SPA in the shared language, a Lambda `GET /share` that renders static OpenGraph/Twitter meta HTML for crawlers (then redirects a human into the SPA), and a Lambda `GET /og` that returns a 1200×630 `image/svg+xml` card. Both Lambda outputs come from pure, dependency-free builders in `@mlb/shared` (`buildShareHtml`, `buildOgImageSvg`), are cached in DynamoDB keyed by seriesId + series situation + lang, and carry the localized "reference values, not betting advice" disclaimer. CloudFront routes `/og*` and `/share*` to the HTTP API so crawlers reach the Lambda-rendered tags instead of the SPA shell.

Watch for: (1) **confirmed** — in production the share HTML derives its public origin from the request `Host` header, but the new CloudFront behaviors use `ALL_VIEWER_EXCEPT_HOST_HEADER` and `SITE_ORIGIN` is never injected, so the Lambda sees the execute-api host and emits `og:url`/`canonical`/`og:image` pointing at the raw API domain rather than the CloudFront site origin. (2) **confirmed** — the API's CORS `allowOrigins` was widened to `['*']` to break a CloudFront↔API synth cycle; a deliberate, documented trade-off worth a conscious sign-off. (3) **possible** — the clipboard/manual-copy fallback copies only the URL, dropping the disclaimer that the Web Share path includes.

**Verdict**: NEEDS_CHANGES

## High-level view

The OGP approach is Lambda-at-request-time, not build-time: a pure `buildOgImageSvg` renders a deterministic SVG, cached in DynamoDB under a key that encodes the series win-count situation and language, so a game result naturally rotates the key and invalidates the card. SVG (not PNG) is a deliberate call to avoid a native rasterizer in the bundle; the honest cost — some crawlers won't render an SVG `og:image` — is documented in the specs and both READMEs along with a PNG upgrade path.

Crawler readability is solved by a dedicated `/share` path rather than User-Agent sniffing. CloudFront forwards `/og*` and `/share*` to the HTTP API; the share Lambda returns minimal HTML whose head carries the per-series meta tags and whose body redirects a human into the SPA deep link via meta-refresh plus `location.replace`. The weak point is origin resolution: the handler prefers a `SITE_ORIGIN` env var, but CDK never sets it (to avoid a CloudFront↔Lambda cycle) and the CloudFront behavior strips the Host header, so the runtime-derived origin is the API domain, not the public site.

The disclaimer is centralized in one `SHARE_DISCLAIMER` constant and reaches all three surfaces: the SVG footer, the share HTML `og:description`, and the on-screen prediction text. The frontend Share button's Web Share payload includes it; the copy fallback does not.

The `?lang=` permalink sets the SPA's initial language with correct precedence (explicit prop → query → persisted → default) and persists the query choice so later query-less navigation keeps it. The two new Lambdas carry only `TABLE_NAME` and no Bedrock env or IAM, and the stack test now asserts exactly one function is granted `bedrock:InvokeModel`.

### Origin resolution contradicts the CloudFront behavior

`getShareHtml` resolves the public origin in priority order: `SITE_ORIGIN` env → forwarded `Host` (+ `X-Forwarded-Proto`) → `http://localhost:5173`. The stack comment is explicit that `SITE_ORIGIN` is deliberately *not* injected to avoid a CloudFront↔Lambda cyclic dependency, so production always lands on the header path. But the `/og*` and `/share*` behaviors attach `OriginRequestPolicy.ALL_VIEWER_EXCEPT_HOST_HEADER`, which drops the viewer Host; API Gateway then sees its own execute-api host. The handler's `header('host')` therefore yields `<id>.execute-api.<region>.amazonaws.com`, and every absolute URL the builder emits is derived from it:

```
og:url / canonical  -> https://<api>/season/2024/series/<id>?lang=en
og:image            -> https://<api>/og?season=2024&seriesId=<id>&lang=en
<meta refresh> url  -> https://<api>/season/2024/series/<id>?lang=en
```

Two consequences. The crawler records a canonical/`og:url` on the API domain, not the public CloudFront site — so shares de-duplicate and attribute to the wrong origin, and a crawler that follows the canonical lands on the API host. And the `og:image` URL points at API Gateway directly, bypassing the `/og*` CloudFront behavior and its cache policy, so the SVG is served uncached from the Lambda path and loses the query-keyed edge caching the infra set up. The meta-refresh/`location.replace` target also sends a human to `https://<api>/season/...`, which has no SPA behind it.

The handler's own doc comment claims `SITE_ORIGIN` is "injected by CDK," which directly contradicts the stack's note that it is intentionally omitted — a sign the two halves were written against different assumptions. The unit test passes because it sets `SITE_ORIGIN` explicitly or supplies a clean `host` header; neither reproduces the stripped-Host production path. The fix needs to get the real site host to the Lambda without reintroducing the cycle — e.g. a custom origin request header on the CloudFront behavior carrying the distribution domain, which the handler reads ahead of `Host`.

### Disclaimer dropped in the copy fallback

`ShareButton.handleShare` builds `text = \`${title} - ${disclaimer}\`` and passes it to `navigator.share`, but both fallbacks (clipboard `writeText(url)` and the manual-copy input) carry only the URL. A user on a desktop browser without Web Share who copies the link shares a bare URL with no disclaimer in the copied payload. The shared link does resolve to a `/share` page and SPA that both show the disclaimer, so the reference-value framing is still reachable — but the copied text itself drops it. Worth a conscious decision on whether the fallback should copy the title+disclaimer too.

### og:image bypasses the CloudFront cache

The `/og*` and `/share*` behaviors cache on the full query string (`CacheQueryStringBehavior.all()`), so distinct `?season=&seriesId=&lang=` combinations are edge-cached as distinct objects — but only when the request arrives through CloudFront. Because `resolveOrigin` yields the execute-api host (see above), the `og:image` URL baked into the share HTML points straight at API Gateway and never traverses the `/og*` behavior, so that edge cache is dead for crawler-fetched images; they fall back to the Lambda + DynamoDB cache path. Resolving the origin concern restores the intended edge caching.
