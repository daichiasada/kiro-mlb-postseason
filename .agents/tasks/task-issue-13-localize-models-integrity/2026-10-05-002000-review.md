# Localized narratives, selectable Amazon-family Bedrock models, and a finished-context data-integrity check (v2)

Fix commit `594605e` resolves all three issues raised in the v1 review (NEEDS_CHANGES). The Amazon Nova InvokeModel body now carries the required top-level `schemaVersion: "messages-v1"`, so the default model's requests are shaped to Nova's native contract instead of being rejected and silently degraded to the fallback. Strategy selection is now driven by the shared allowlist's `provider` discriminator and throws when a declared provider has no registered adapter, closing the "future third provider silently shaped as Nova" trap. The Nova shaping test now pins `schemaVersion`, and a new describe block pins provider-driven selection across every allowlist id plus the unrecognized-id default. The Anthropic path is byte-for-byte unchanged, and the deterministic fallback, lenient parsing, integrity semantics, and i18n completeness are untouched by the fix.

Watch for: nothing blocking. The one residual observation is that `strategyForModel`'s throw path for an allowlisted-but-adapterless provider cannot be unit-tested without a fourth provider in the allowlist, so it is covered by reasoning rather than a test — acceptable, since the compiler enforces `STRATEGY_BY_PROVIDER` exhaustiveness over the current provider union (possible).

**Verdict**: APPROVED

## High-level view

The Nova request body gap is closed: `amazonNovaStrategy.buildBody` emits `schemaVersion: "messages-v1"` as a sibling to `messages`/`inferenceConfig`, matching Nova's documented native request schema. Because the default model is Nova Lite and any invoker error is swallowed into the deterministic fallback, this was the one change that determined whether the AI path actually runs for the default selection; it now does.

Adapter selection no longer relies on an id-substring catch-all. `strategyForModel` resolves the provider from `NARRATIVE_MODEL_OPTIONS[].provider` (via a `PROVIDER_BY_MODEL_ID` map), applies the id-substring heuristic only to ids outside the allowlist, and throws if an allowlisted provider has no entry in `STRATEGY_BY_PROVIDER`. A wholly unrecognized id still defaults to Nova, consistent with `resolveModelId`. The two sources of truth (allowlist `provider` and id substring) are no longer parallel and divergent — the allowlist is primary and the heuristic is a narrow fallback for raw overrides.

The test contract was tightened to match: the real-invoke shaping test asserts `schemaVersion === 'messages-v1'`, and a new suite proves selection is `provider`-driven by producing a request body per allowlist id and checking it carries the Nova or Anthropic discriminator its declared provider implies. The missing-field regression that passed CI green in v1 would now fail a test.

Everything else the v1 review examined — language threading end to end, the integrity check's finished-vs-scheduled gating, the pure-aggregator/handler-attached surfacing, and the EN/JA message completeness — is unchanged by the fix commit, which touched only `narrative.ts` and its test.

### v1 issue 1 — Nova `schemaVersion` (resolved, confirmed)

`amazonNovaStrategy.buildBody` now emits `schemaVersion: 'messages-v1'` as a sibling to `messages`/`inferenceConfig`, so Nova requests conform to the native InvokeModel contract. The real-invoke shaping test asserts `sentBody.schemaVersion === 'messages-v1'`, so a future drop of the field fails the suite rather than silently degrading every Nova selection to the templated fallback.

### v1 issue 2 — provider-driven adapter selection (resolved, confirmed)

Selection flows through `PROVIDER_BY_MODEL_ID.get(modelId) ?? providerFromIdHeuristic(modelId)`. For every allowlist id the provider comes from the shared `NARRATIVE_MODEL_OPTIONS[].provider` discriminator — the single source of truth — so the id-substring match is reached only for ids absent from the allowlist (raw `BEDROCK_MODEL_ID` overrides). The resolved provider indexes `STRATEGY_BY_PROVIDER`; a declared provider with no registered adapter throws `No Bedrock request/response adapter for provider '<p>'` instead of falling through to Nova. A wholly unrecognized id (no allowlist entry, no `anthropic.`/`amazon.` substring) still defaults to Nova, which matches `resolveModelId`'s own default-to-Nova-Lite behavior, so the two resolution paths agree.

The throw is a deliberate fail-loud: if the allowlist ever grows a third provider without a matching adapter, the mismatch surfaces at invoke time rather than being masked as a mis-shaped Nova request that fails into the fallback. `STRATEGY_BY_PROVIDER` is typed `Record<NarrativeModelProvider, ModelStrategy>`, so the compiler already forces an entry for every member of the current provider union; the runtime throw guards the case where a provider is added to the union/allowlist but the record is updated out of step.

### v1 issue 3 — test contract pins the schema (resolved, confirmed)

Beyond the `schemaVersion` assertion in the real-invoke test, a new `strategyForModel provider selection` describe block identifies the chosen strategy by the body it produces and asserts: every `provider === 'amazon'` allowlist id yields a Nova body (`schemaVersion`/`inferenceConfig`, no `anthropic_version`); every `provider === 'anthropic'` id yields an Anthropic body (`anthropic_version`, no `inferenceConfig`); the mapping holds for all allowlist entries driven by `provider`; and a non-allowlisted unrecognized id (`'made-up-model'`) resolves to Nova. This pins the selection contract so a regression to id-substring-only routing, or a swap of the two bodies, fails a test. The suite is now 26 tests (up from 22 at v1), all passing.

The one path not directly asserted is the throw for an allowlisted provider missing an adapter — it cannot be triggered without adding a fourth provider to the allowlist, and doing so purely as a test seam would violate the "no test-only production constructs" rule. Compile-time exhaustiveness of `STRATEGY_BY_PROVIDER` plus the explicit runtime throw make this acceptable without a dedicated test. (possible)

### Regression surface (confirmed clean)

The fix commit's source change is confined to `backend/src/bedrock/narrative.ts` and `backend/src/bedrock/narrative.test.ts`. The Anthropic strategy (`anthropic_version: 'bedrock-2023-05-31'`, `max_tokens`, `temperature`, `content: [{ type: 'text', text }]`, and the `type === 'text'` content-block parser) is byte-for-byte what shipped before, so the working Claude path carries no regression risk. The narrative suite's fallback tests confirm `generateNarrative` still returns the EN and JA deterministic narratives when the invoker throws, so error-swallowing-to-fallback behavior is intact. Nothing in the fix touches `parseLanguage`/`parseModelId` leniency (never 400), `findIntegrityWarnings` gating, the handler-attached `integrityWarnings` surfacing, or the EN/JA message tables — all of which the v1 review verified and none of which the fix commit modified.
