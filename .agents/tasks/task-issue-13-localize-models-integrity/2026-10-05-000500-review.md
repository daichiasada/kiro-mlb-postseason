# Localized prediction narratives, selectable Amazon-family Bedrock models, and a finished-context data-integrity check (v1)

Issue #13 threads the UI language (EN/JA) end to end so the AI prediction narrative — both the Bedrock prompt and the deterministic fallback — is produced in the viewer's language, makes the Bedrock model selectable from a shared allowlist (defaulting to Amazon Nova Lite, with the previous Claude Haiku kept as an option), teaches the Bedrock invoker a per-provider request/response shape so Anthropic and Amazon Nova are addressed with their respective native InvokeModel contracts, and surfaces a non-blocking data-integrity warning when a finished series or decided game still references a placeholder/TBD team id. Language and model are both lenient optional controls that never produce a 400; unknown values fall back to the server default via the shared allowlist. The integrity scan is a pure `@mlb/shared` function attached to the `/bracket` response by the handler, leaving the aggregator side-effect free. The user-requested completion hook (`handle-open-issues-on-task-complete.kiro.hook`) is included in the change set.

Watch for: the Amazon Nova InvokeModel request body omits the `schemaVersion: "messages-v1"` field that Nova's native request schema documents, which can cause Nova to reject every call and silently route all Nova selections to the deterministic fallback (likely); the per-provider strategy selector resolves an unknown model id to the Nova strategy, so a future non-Amazon/non-Anthropic allowlist entry would be shaped as Nova (possible). Both the Anthropic path and the results-only/final/upcoming short-circuits are preserved and well covered.

**Verdict**: NEEDS_CHANGES

## High-level view

The Bedrock invoker now picks a request/response adapter from the model id: Anthropic ids keep the exact `anthropic_version` + `messages[].content[].text` body and content-block parsing that previously shipped, while Amazon ids get a Nova-style `messages` + `inferenceConfig` body parsed from `output.message.content[].text`. The Anthropic path is byte-for-byte what it was, so the working Claude flow carries no regression risk. The Nova body, however, leaves out the `schemaVersion` field that Nova's native InvokeModel schema requires; because any invoker error is swallowed into the deterministic fallback, a rejected Nova call wouldn't surface as a 500 — it would quietly degrade every Nova selection to the templated narrative, which defeats the point of making Nova the default.

Language is threaded UI → `getPrediction(&lang=)` → handler (`parseLanguage`, region-subtag tolerant, never 400) → service → `buildPrompt`/`fallbackNarrative`, both of which branch on language and are asserted to emit genuinely localized prose (not an ignored param). The model control is threaded the same way and resolved server-side against the single shared allowlist in `@mlb/shared`, so the UI and API cannot desynchronize on which models exist.

The integrity check correctly distinguishes a finished placeholder (a `status:'final'` series, or a game with a decided winner, that references an id absent from `TEAMS`) from a normal not-yet-started scheduled placeholder, which it never flags. It is pure and dependency-free, attached in the handler with a server-side log, and rendered as a localized non-blocking banner. The strategy selector's fallthrough for an unrecognized provider silently assumes Nova shaping rather than failing loudly, which is a latent trap if the allowlist ever grows a third provider.

### Per-provider Bedrock adapter and the Nova contract gap

The invoker selects a `ModelStrategy` from the model id and uses it for both request shaping and response parsing. The Anthropic strategy is unchanged from the prior Claude implementation: `anthropic_version: 'bedrock-2023-05-31'`, `max_tokens`, `temperature`, and a single user message with `content: [{ type: 'text', text }]`, parsed by filtering `content[]` to `type === 'text'` blocks and concatenating their text. That exact preservation is why the existing Claude path carries no regression risk, and the shaping test pins every field of the Anthropic body.

The Amazon Nova strategy sends:

```json
{
  "messages": [{ "role": "user", "content": [{ "text": prompt }] }],
  "inferenceConfig": { "maxTokens": 300, "temperature": 0.5 }
}
```

Amazon Nova's native InvokeModel request schema documents a required top-level `schemaVersion: "messages-v1"` sibling to `messages`/`inferenceConfig`. It is absent here. The response parser (`output.message.content[].text`) matches Nova's documented response shape, so the read side is correct; the gap is on the request side. The practical consequence is not a crash: `generateNarrative` catches any invoker throw and returns `fallbackNarrative` with a `${modelId} (fallback)` model tag. So if Nova rejects the body, every Nova selection — including the new default (Nova Lite) — silently serves the deterministic templated narrative instead of a model-generated one, and nothing at the API surface distinguishes that from Bedrock being unavailable. This should be verified against a live Nova invoke; adding `schemaVersion: 'messages-v1'` is the low-risk fix. (likely)

`strategyForModel` resolves `amazon.`→Nova, `anthropic.`→Anthropic, and anything else→Nova. The allowlist already carries a `provider` discriminator per option, so the id-substring routing is a second, parallel source of truth. Today it agrees with the allowlist, but the catch-all defaulting to Nova means a future third-provider entry would be silently shaped as Nova and fail into the fallback with no distinguishing signal. Driving the strategy from the option's `provider` field, or throwing on an unrecognized provider, removes the latent trap. (possible)

### Language threading end to end

`parseLanguage` lowercases, trims, and drops a region subtag (`en-US`→`en`, `ja-JP`→`ja`), recognizes only `en`/`ja`, and returns `undefined` for anything else — never a 400. The service defaults a missing language to `DEFAULT_NARRATIVE_LANGUAGE` and passes it to `generateNarrative`, which uses it for both `buildPrompt` and `fallbackNarrative`. Both functions branch on language and emit distinct prose: the JA prompt carries `野球アナリスト`/`日本語` and the EN prompt carries `concise baseball analyst`, with team club names and the numeric percentage held identical across languages per the i18n convention. This is a real localization, not an ignored parameter — the service test asserts the JA prompt (`野球アナリスト`) actually reaches the injected invoker, and the narrative unit tests assert the EN/JA prompt and fallback each contain the other language's absence.

On the frontend, `PredictionPanel`'s fetch effect lists `lang` and `model` in its dependency array, so toggling the header language or picking a model re-requests; `api.getPrediction` appends `&lang=`/`&model=` only when defined and URL-encodes them. The component test toggles the live i18n language and asserts a re-fetch with the new `lang`, and the POST/GET handler tests confirm `lang`/`model` from either query or body, including that an unknown `lang`/`model` still yields 200.

### Integrity check semantics and surfacing

`findIntegrityWarnings` flags exactly two finished contexts: a `status:'final'` series whose high or low seed id is absent from `TEAMS`, and a game with a decided winner (`away.isWinner === true || home.isWinner === true`) whose participant id is absent from `TEAMS`. A scheduled or in-progress series with placeholder seeds is deliberately not flagged — the normal state of a not-yet-determined bracket — and the game-level check fires independently of series status so a decided game inside an in-progress series is still caught. Output is de-duplicated by identity key and stably ordered by round, series id, scope, team id, then gamePk, so the result is deterministic regardless of input game order. The fast-check property suite proves the defining invariants hold over randomized brackets: every flagged id is a non-`TEAMS` id, series-scope warnings come only from final series, game-scope warnings come only from decided games, and the list is dedup'd and never throws — a property that would fail if the status/decided gating were loosened.

The aggregator stays pure: the warning array is computed in `getBracket.ts` and attached to the 200 response as an optional `integrityWarnings`, with a concise `console.warn` for server-side observability. The handler test drives a crafted final series referencing a placeholder id through the real aggregate path and asserts the 200 body carries the warning and that exactly one warning is logged. The frontend reads `bracket.integrityWarnings?.length` and renders a localized `integrity.banner` (present in both EN and JA message tables) as a non-blocking notice, so an older consumer that ignores the optional field is unaffected.

### Test quality

The suites exercise the real paths rather than mocking away the logic under test. The `RealBedrockInvoker` shaping test injects a stubbed `BedrockRuntimeClient.send`, captures the actual `InvokeModelCommand`, and asserts the serialized body per provider (Anthropic carries `anthropic_version`; Nova carries `inferenceConfig` and no `anthropic_version`, with content blocks lacking a `type` field) plus multi-block concatenation and the empty-content throw for both providers — this would fail if the two bodies were swapped or merged. Its one blind spot is that it does not assert the presence of Nova's `schemaVersion`, which is precisely why the missing field passed CI green. `resolveModelId` is tested for pass-through of each allowlisted id and fallback-to-default for unknown/undefined. The frontend selector test asserts every shared option renders and that choosing Nova Pro re-requests with that id.

Not tested: a live-contract assertion that the Nova request body matches Amazon's documented schema (the gap above); and the strategy selector's unknown-provider fallthrough (no test pins what a non-amazon/non-anthropic id resolves to).

### Infra and the Claude regression surface

The stack default `BEDROCK_MODEL_ID` moves to `us.amazon.nova-lite-v1:0`, matching the shared default, and the IAM grant already spans `foundation-model/*` and `inference-profile/*`, which covers both the Nova profiles and the retained Claude profile, so no per-model IAM change is needed. The results-only (season < current), series-level final, and upcoming/not-started short-circuits in `bracketService.getPrediction` are unchanged and still return before touching the predict model or Bedrock; the model/language resolution happens only on the `mode:'prediction'` path after those guards. The i18n `MessageKey` union is closed and both `prediction.model.selectLabel` and `integrity.banner` are present in EN and JA, so the new UI strings are complete in both languages.
