# Favorite teams: persisted store, bracket highlight, header pin, and filter (v1)

Issue #18 adds favorite teams end to end: a guarded localStorage store with pure immutable helpers, a React context, an accessible star toggle on every team row, a non-color favorite highlight on series cards with an eliminated badge, a header "pin" summarizing each favorite's current standing, and a "show only my teams" filter over the bracket. All derivation logic lives in pure helpers (`favorites.ts`, `bracketLayout.ts`) with thin React glue on top. All three acceptance criteria are met: the highlight is a dashed outline + star icon + screen-reader label (not color), elimination switches to a localized "Eliminated"/"敗退" indication in both the pin and the card, and EN/JA parity holds (verified by a dictionary-parity test).

Watch for: a dead i18n key (`favorites.header.status.inProgress`) that `statusLine` never reaches — cosmetic, not blocking (confirmed). An advancing-between-rounds favorite with no in-progress/scheduled series renders a slightly imprecise "starts soon" status (likely, low impact). No correctness, a11y, or regression blockers found.

**Verdict**: APPROVED

## High-level view

`readStoredFavorites` guards against SSR/jsdom, non-JSON, non-array, and non-integer entries, de-duplicating survivors in first-seen order, so a corrupt `mlb.favorites` value can never crash the app. The context persists every mutation through the pure add/remove/toggle helpers so storage and state cannot diverge.

The accessibility requirement is met by construction rather than by color. The star toggle and the series marker swap SVG *shape* (filled vs hollow star) with state, the highlighted card carries a thick dashed outline plus a star-icon marker, and a visually-hidden `favorites.marker` label announces the series to assistive tech. Toggles are native buttons with `aria-pressed` and localized `aria-label`s.

Elimination is derived once over the whole bracket (lost a FINAL series) and surfaced consistently in two places: the card team row shows an "Eliminated"/"敗退" badge, and the header pin's status line short-circuits to the same localized string. Champion detection (won a FINAL World Series) is distinguished from both active and eliminated, matching the existing `computeStandings` derivation.

The filter runs *after* `buildRoundColumns`, so the roving-tabindex grid treats a filtered bracket exactly like a season-switch-shrunken one — the active-cell clamp already handles the shape change, and the #22 keyboard model is untouched because the added inner star button is ignored by the card's `event.target !== event.currentTarget` guard.

### Guarded store and corrupt-storage handling

`readStoredFavorites` is the trust boundary for untrusted persisted input and it closes every obvious hole: a `typeof localStorage === 'undefined'` guard for SSR/jsdom, a try/catch around `getItem`/`JSON.parse` so a throwing storage (private mode, blocked) or non-JSON string returns `[]`, an `Array.isArray` check so a JSON object returns `[]`, and an `isTeamId` filter (finite, integer, non-negative) that drops strings, `NaN`, floats, and `null` before de-duping in first-seen order. The test feeding `[119, '147', 119, 1.5, null, 158, 158]` and expecting `[119, 158]` would fail if any guard were loosened, and a `getItem`-throws spy proves the read never propagates. Writes swallow quota/SSR failures symmetrically.

The context computes each next list with the pure helper, persists it, and returns it as the new state inside the same updater, so localStorage and React state are written from one value and cannot drift. `initialFavorites` is a test seam only.

### Non-color highlight and the two elimination surfaces

The highlight satisfies criterion (1) three ways over, none of them color-dependent: `series-card--favorite` applies a 3px dashed outline (perceivable in grayscale), the header renders a filled-star SVG marker (`data-testid="favorite-marker"`), and an `sr-only` span carries the localized `favorites.marker` text for assistive tech. The star toggle itself encodes state in the SVG `fill` (`currentColor` when on, `none` when off) — a shape change, not just a color change — and exposes `aria-pressed` plus a localized add/remove `aria-label`.

Elimination (criterion 2) is derived in `isTeamEliminated` as "lost at least one FINAL series," which correctly treats a World Series *loser* as eliminated and a champion or still-active team as not. It is surfaced in both required places from the same derivation: `SeriesCard`'s `TeamRow` shows a `.series-team__eliminated` badge for a favorited, eliminated team, and `FavoritesPin`'s `statusLine` short-circuits to `t('favorites.eliminated')` before any record-based branch. The card derives elimination over the whole `bracket` prop when provided (a team can be eliminated by a final *elsewhere* in the bracket), falling back to the single series only in isolation; the test favoriting the Wild Card loser against `sampleBracket` confirms the bracket-wide scope.

```
favorite id ──┬─ SeriesCard  ─ isTeamEliminated(bracket) ─→ "Eliminated"/"敗退" badge on team row
              └─ FavoritesPin ─ favoriteSummary(bracket).eliminated ─→ "Eliminated"/"敗退" status line
```

### favoriteSummary status derivation and its edges

`favoriteSummary` is a clean state machine: not-in-bracket yields `inBracket:false` (and the pin renders nothing for it, verified), eliminated and champion are flagged independently, `furthestRound` comes from the round-ordered series list, and `currentSeries` prefers an in-progress series then the earliest scheduled one. The record is computed from the favorite's own perspective (the test on team 158 expecting `{wins:0, losses:1}` as the trailing side would fail if the high/low perspective were swapped).

Two soft edges, neither blocking. First, `favorites.header.status.inProgress` exists in both dictionaries but `statusLine` only emits leading/trailing/tied for an in-progress series, so that key is dead — it will keep passing the key-parity test while never rendering. Second, a favorite that has *won* its furthest round but whose next series is not yet scheduled has `currentSeries === null`, so `statusLine` falls to `favorites.header.status.scheduled` → "{round}, starts soon" naming the already-finished round; it reads slightly wrong but is low-impact and only appears in a transient between-rounds state.

### Filter and the preserved roving-tabindex model

`BracketView` builds the deterministic round/league columns first and only then filters each column to series containing a favorite, dropping now-empty columns. Because the filter changes the grid the same way a season switch does, the existing active-cell clamp (`Math.min`/`Math.max` against the current `columnLengths`) already keeps exactly one card tabbable, and `favoritesOnly` with zero surviving columns renders a localized empty state with `role="status"` instead of an empty grid. The page keeps `favoritesOnly` at the page level so it survives season switches, which is what lets the empty state appear after switching to a season where no favorite plays.

The #22 keyboard model is intact. The card's `handleKeyDown` bails whenever `event.target !== event.currentTarget`, so the newly added inner star button keeps native Enter/Space behavior and the card never double-activates; the star's `onClick` only toggles and never navigates, so mouse users have no double-activation path either (there is deliberately no card-body onClick). The HomePage filter test flips the toggle and asserts the non-favorite ALCS card disappears while the favorite WS card stays, which would fail if filtering happened before column building or clobbered the grid.

### Test coverage

The new tests exercise behavior, not static values. `favorites.test.ts` drives every guard branch (absent/non-JSON/non-array/dirty-array/throwing-storage) and the immutability of the array helpers. `bracketLayout.test.ts` builds a single fixture covering won-final, lost-final, in-progress, champion, WS-loser, and not-in-bracket, and asserts `findTeamSeries` round-ordering independent of array order. `HomePage.favorites.test.tsx` covers the four user-visible outcomes (no pin, active pin, eliminated pin, filter + empty state) against a mocked bracket, and the Playwright `favorites.spec.ts` repeats them in JA including the `敗退` badge inside the card. These would all fail if the corresponding logic were reverted.

Not tested: an explicit assertion that pressing Enter/Space while focus is on the inner star button does not navigate the card (the guard is covered only indirectly by the general keyboard spec); and the between-rounds "starts soon" wording edge noted above has no fixture.
